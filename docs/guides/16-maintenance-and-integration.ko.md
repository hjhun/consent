# 가이드 16: 코드 유지보수와 제품 연동

[English](16-maintenance-and-integration.en.md)

프레임워크 코드를 변경하거나 제품 연동을 준비할 때 이 목록을 사용하세요.
구현된 자원 수명 보호와 플랫폼 계약 또는 기기 증거가 더 필요한 작업을 정리합니다.

## 1. 자원과 콜백 소유권 점검하기

콜백은 실행 중 소유자를 유지하고 예외를 차단하며 불확실한 권한 상태를 닫아야
합니다. 프로필 콜백은 `noexcept` 어댑터를 사용하고 타이머는 콜백이 자기 source를
제거해도 실행 데이터를 유지합니다. 수명 관리 객체와 SQLite 소유자는 복사할 수
없습니다. SQLite 오류 버퍼는 `sqlite3_free`로 해제하며 클라이언트 동기화는
공통 `MutexLock`을 사용합니다.

프로필 설정은 해석과 검증을 마친 뒤에만 공개합니다. 설정이 없으면 기존 동작을
유지하고 잘못된 파일이 있으면 시작을 거부합니다. 필수 문자열의 GLib 오류를
확인하므로 명시적 `subsession=`는 유효하지만 `subsession=\x`는 거부합니다.
보호된 파일 열기, 제한된 전체 읽기와 NUL/중복/알 수 없는 key 거부로 불완전하거나
모호한 설정을 막습니다.

실행한 제공자 프로세스는 회수할 때까지 process helper가 소유하며 설정 실패도
같이 처리합니다. 비동기 프로필 예제는 대기 결과 하나를 소유하고 client 해제 성공
뒤 정리하며 결과를 한 번만 이전합니다. 리팩토링 때 ABI, 프로토콜, 역할, 세대
차단과 저장소 동작을 유지하세요. Version map은 링크 의존성이므로 공개 심볼 변경
시 다시 링크합니다.

## 2. 제품 연동 작업 선택하기

| 작업 | 필요한 계약 또는 증거 |
| --- | --- |
| CM/CE 어댑터 | 신뢰 서비스 신원, capability/record 연결, 최종 AUTHORIZE, 최신 CE 소스와 등급 |
| Installer hook | plugin별 설치/갱신/삭제 트랜잭션, 인증 publisher/offline handle, 보호된 package/app 세대 |
| 승인 UI | 제품 빌드/endpoint 패키징, 신뢰 UI 역할, argo 실행 연결, 고정 라이브러리 계약 |
| 프로필 | 보호된 sessiond 계정/프로필 연결, bus 권한, 실제 제공자 조율 |
| Holder 정리 | 실제 데이터 삭제와 인증된 재시도 가능 ACK |
| Registry 복구 | 전체 손실 뒤 신뢰할 정의 생산자, 승인 복원 금지 |
| 내구성과 부하 | 저장/전원 중단 및 실제 지속 부하 검사 |

기존 NUI 코드는 재사용할 수 있으나 고정 라이브러리를 임의 실행 인자로 바꾸지
않습니다. 프로필 조사에서는 설치된 sessiond의 비활성 상태, bus 소유자 부재와
설정 부재를 확인했습니다. 그 관찰만으로 비활성 원인을 확정하지 않았습니다.
합성 예제의 성공만으로 위 제품 작업이 완료되지는 않습니다.

## 3. 보관한 검증 결과와 비교하기

Release26 r2 GBS는 0으로 종료했고 27개가 통과했으며 root 전용 4개를
건너뛰었습니다. 설정 해석, 콜백 예외 차단과 자식 프로세스 정리 검사가
통과했습니다. 설치된 profiles/mock/tools/default는 0, 제품 strict는 예상 코드 1,
정리 다섯 번은 모두 0이었습니다. 설치 파일 162개의 RPM hash와 네이티브
설정/프로세스 검사 종료 코드 0을 확인했습니다. 운영 daemon18과 PoC18은 유지했습니다.

증거: `/var/tmp/consent-artifacts/consent-style-06/`. 상세 결과와 실패 이력은
[검증 상세 기록](../history/07-verification-history.ko.md#guide-16-checkpoint).
